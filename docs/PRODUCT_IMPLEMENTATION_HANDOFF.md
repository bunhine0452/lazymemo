# LazyMemo 제품 재설계 — 다음 세션 구현 인계서

2026-09-22 · 작성: Codex · 상태: **사용자 방향 승인, 구현 시작 전**

## 1. 다음 세션이 가장 먼저 알아야 할 것

사용자는 기능 조사 보고서를 읽고 **“너의 조사와 의견대로 구현할거야”**라고 승인했으며, 다음 세션이 사용할 인계서를 요청했다. 채택 방향은 **적은 것을 놓치지 않게 돕는 메모 앱**이다. 이 방향을 다시 선택해 달라고 묻거나 조사만 반복하지 말고, 최신 코드를 확인한 뒤 아래 순서대로 구현한다. 성공의 기준은 기능 수가 아니라 사용자가 실제 일을 놓치지 않고 끝내는 경험이다.

이 인계서를 만든 세션은 제품 코드를 수정하지 않았다. 조사·방향 결정·구현 계획만 완료했다. 출시 성공이나 실제 사용자 수요가 검증된 상태는 아니다. 구현 과정에서 반증이 나오면 근거를 기록해 수정하되, 임의로 다시 범용 AI 비서 확장으로 돌아가지 않는다.

이 인계서는 기존의 ‘자동 질문’, ‘날짜가 지나면 정리’, ‘질문처럼 보이면 비서로’와 충돌하는 부분을 **의도적으로 변경**한다. 과거 설계 원칙이 있다는 이유로 새 방향을 되돌리지 않는다. 파일 소유권·원문 보존·권한 동의·되돌리기 원칙은 유지한다.

## 2. 제품의 중심 — 무엇을 완성할 것인가

**대표 경험: 바로 남기기 → 필요한 때 원문과 함께 다시 보기 → 그 자리에서 완료하거나 미루기.**

첫 대상은 맥으로 일하고 아이폰으로 약속·링크·짧은 할 일을 받지만, 적은 것을 다시 찾거나 처리하는 데 자주 실패하는 사람이다. 기존 메모 앱 전체를 옮기게 하지 말고 오늘의 몇 가지부터 맡길 수 있게 한다.

세 가지 완성 장면:

1. 작업 중 단축키로 ‘내일 견적 보내기’를 남긴다. 실제 저장 결과와 알림 여부가 보인다. 끝내지 못하면 날짜가 지나도 찾을 수 있고 완료하면 양 기기에 반영된다.
2. 폰에서 받은 예약 링크를 공유한다. 원문·시각·장소가 함께 남고, 알림을 눌러 필요한 원문으로 돌아온다. 앱 미실행으로 예약되지 않았다면 그렇게 표시한다.
3. 읽을 자료를 저장하고 다시 볼 때를 정한다. 정한 시점에 나타나고, 읽은 뒤 보관하거나 다시 미룬다. 매일 반복해서 방해하지 않는다.

기존 종이·색·타이포·바탕화면 정체성, 한국어 입력·초성 검색, 위젯·Siri·공유, 로컬 파일 소유권을 살린다. 화면 전면 재디자인이나 프레임워크 교체를 선행 조건으로 만들지 않는다. AI는 명시적으로 요청하는 보조 기능이며 모델 없이 위 세 장면이 완결돼야 한다.

## 3. 이미 확인한 사실과 아직 재현할 것

| 항목 | 근거 수준 | 다음 세션의 처리 |
|---|---|---|
| 어제의 다시 보기가 자정 뒤 ‘지금’에서 빠짐 | 코드·기존 테스트에 명시 | 의도된 현행 동작을 새 정책에 맞게 변경 |
| 지난 일정 정리가 미완료 체크리스트보다 먼저 적용 | 코드 확인 | 날짜 있는 미완료 사례를 새 테스트로 고정 |
| 미래 `surface`가 있어도 과거 일정 정리 대상 | 정적 결함 후보 | 현재 소스로 실패 재현 후 수정 |
| `untidy`가 갱신한 `updated`를 과거 일정 정리가 읽지 않음 | 정적 결함 후보 | 복원→정리 재현 후 수정 |
| 질문·명령 키워드가 일반 메모 저장보다 먼저 분기 | 코드 확인 | 사용자 입력의 기본 동작을 변경 |
| 공유 저장과 일반 Recall 예약이 분리됨 | 코드·운영 문서 확인 | 확장 실행 제약을 확인하고 상태/예약 경로 보완 |
| 초안 쓰기 실패가 호출자에 드러나지 않음 | 코드 확인 | 실패 주입으로 UI·복구 검증 |
| 충돌의 진 판본이 휴지통에 보존됨 | 코드·기존 테스트 확인 | 유실이라고 단정하지 말고 발견·복구 경험 개선 |
| 이런 문제가 실제 이탈의 원인임 | **미확인** | 사용자 관찰로 검증; 단정 금지 |

이전 실행: `./scripts/test.sh --skip-build --filter 'RecallTests|TidyRuleTests|CommandResolverTests|ConflictSettlementTests'` → 7개 스위트 46개 통과. **기존 빌드 실행이므로 최신 소스 검증이 아니다.** 이번 인계서를 근거로 ‘최신 회귀 테스트 완료’라고 적지 않는다. 실제 앱 조작·실기기 알림·동기화·사용자 인터뷰는 수행하지 않았다.

## 4. 구현 전 확정한 동작 계약

### 입력과 저장

- 기본 캡처의 확정은 메모를 저장한다. 물음표·‘왜’·‘어디’·‘알림’·‘폴더’가 들어 있어도 비서로 자동 전환하지 않는다.
- 날짜 칩은 유지하고 해석을 취소·수정할 수 있게 한다. 날짜 추출 때문에 기록한 원문을 복구할 수 없게 만들지 않는다. 본문을 그대로 보존하거나 원문 필드를 별도로 보존하는 최소 변경안을 택하고 왕복 저장 테스트로 보장한다. 기존 파일에 원문이 없으면 추측해 만들지 않는다.
- 검색 결과를 명시적으로 선택해 여는 행동은 유지한다. 기본 저장과 결과 열기의 키/버튼 의미가 모호하지 않게 한다. 선택하지 않은 결과가 저장을 가로채면 안 된다.
- 비서 버튼을 누르거나 기존 비서 대화에 명시적으로 들어간 경우 질문·명령 기능을 유지한다. 비서 요청을 저장 메모로 무조건 바꾸는 회귀를 만들지 않는다.
- 저장이 끝나면 다음 입력을 받는다. 길찾기·약속 시각 보완은 결과 카드의 선택 행동이다. 뒤이어 적은 문장을 앞 메모의 답변으로 소비하지 않는다.
- 초안은 아직 확정되지 않은 기기 로컬 기록이다. 초안 보존·메모 저장·알림 예약을 같은 성공 표시로 합치지 않는다.

### 완료·보관·오늘 숨김

| 상태/행동 | 필수 의미 |
|---|---|
| 완료 | 사용자가 일을 끝냈다는 의사. 파일에 저장해 동기화, 되돌리기 가능 |
| 보관 | 당장 안 볼 기록. 검색·원문은 유지, 완료나 삭제와 동일시하지 않음 |
| 오늘 숨김 | 해당 등장/기기의 표시 억제. 완료로 표현하지 않음 |
| 다시 보기 변경 | `surface`에 해당하는 시각만 변경, 실제 일정은 유지 |
| 일정 변경 | 사용자가 명시적으로 선택했을 때만 약속/마감 이동 |
| 복원 | 사용자의 재노출 의사. 다음 자동 정리 한 번으로 무효화하지 않음 |

- **첫 저장 때 종류 선택을 강요하지 않는다.** 일반 메모를 모두 미완료 할 일로 만들지 않는다. 미완료 체크리스트 또는 사용자가 다시 보기를 요청한 기록은 후속 처리가 필요한 것으로 다룬다.
- 날짜 경과는 완료가 아니다. 미래 다시 보기, 미완료 체크리스트, 명시적 복원은 자동 정리보다 우선한다.
- 완료/보관은 알림 대상에서 제외하고, 복원 시 과거 알림을 즉시 폭주시키지 않는다. 미래 예약과 다음 노출을 사용자에게 설명한다.
- 반복 일정은 회차를 구분한다. 현재 회차 완료가 영구 완료가 되지 않으며, 지난 회차의 체크가 다음 회차를 영구 제외하지 않는다. 자동 회차 이동과 놓친 회차 표시 정책을 같은 테스트에서 확인한다.
- 추천 저장 방향은 완료·명시적 보관·복원 보호를 표현하는 선택적 메타데이터다. 정확한 필드명은 `MemoFile`·기존 `preserved`·구버전 읽기 동작을 확인해 정한다. 표현 방식을 바꾸더라도 위 의미는 유지한다.
- **`tidied`를 완료로 일괄 이행하지 않는다.** 기존 자동 정리에는 사용자의 완료 의사가 없다. 기존 정리 파일을 한꺼번에 전부 현재 화면으로 복원하지도 않는다. 안전한 기존 표시 유지와 개별 복원 경로를 제공한다.

### 다시 보기와 알림

- ‘지금’의 대표 카드는 최대 3개를 유지한다. 별도로 ‘놓친 것/오늘/나중에’의 수와 전체로 가는 경로를 제공한다. 세 장이 전체라고 오해하게 하지 않는다.
- 놓친 미처리는 날짜가 바뀌어도 접근 가능하다. 매일 전부 다시 푸시하지 않는다. 기본은 화면의 조용한 요약이다.
- 표시 우선순위 초안: 처리하지 않은 시간 경과 항목을 요약으로 항상 노출하고, 대표 세 장은 가까운 일정과 사용자가 요청한 다시 보기를 중심으로 선정한다. 오래된 항목이 당일 약속을 모두 밀어내지 않게 한다.
- 저장 직후 예약 결과는 **현재 기기에서 확인한 사실**만 표시한다. 예: ‘이 iPhone에 알림 예약됨’, ‘알림 꺼짐’, ‘앱을 열어 예약 확인 필요’, ‘예약 실패 · 다시 시도’.
- 날짜만 있는 항목은 알림이 없다는 점을 보여 주고, 원하면 기본 시간을 선택하게 한다. 처음 명시적으로 알림을 요청할 때 권한을 요청하며 첫 실행 강제 권한 흐름을 만들지 않는다.
- 공유 확장에서 예약을 수행할 수 있으면 공통 예약 정책·안정 ID를 재사용한다. 확장에서 전체 예약을 잘못 덮거나 본 앱과 중복 예약하지 않는다. 기술적으로 보장할 수 없으면 저장 후 필요한 행동을 명시한다. 가짜 ‘예약 완료’로 UX를 덮지 않는다.
- 서버 없는 현재 구조에서 종료된 다른 기기의 즉시 갱신을 보장하지 않는다. 양 기기 알림 중복을 완전히 제거하는 기능은 별도 기술 근거 없이 약속하지 않는다.

통과 조건: 파일 쓰기 실패·권한 거절·예약 실패·예약 한도·공유 입력·Siri 입력 각각에서 화면의 약속이 실제 결과와 일치한다. 저장 실패면 입력을 지우지 않는다. 재시도 때 메모·알림 중복을 만들지 않는다. 폰 잠금/종료 전달은 기존 `lazymemo-recall#recall-device`에서 실기기로 확인한다.

시간·장소 있는 메모 뒤 ‘우유 사기’를 입력하는 연속 입력 검증을 추가한다. 질문 대기 중 취소·다른 입력으로 돌아오기·저장 실패도 확인한다. 처음부터 실제 자기 메모를 저장하고, 저장 뒤에 필요한 조작 하나만 안내한다. 다섯 장 안내는 도움말로 접근 가능하게 남긴다.

통과 조건: 기본 확정으로 모델 호출 없이 저장; 명시적 비서 기능은 유지; 첫 실제 메모가 튜토리얼 종료 뒤에도 남음; 저장·검색·비서·대화 답변의 상태가 화면에서 분명함.

### 묶음 4 — 처리 상태와 ‘지금’을 양 플랫폼에서 완성한다

플랜: `#memo-state-contract` → `#unfinished-recall`.

중심: [Memo.swift](../Sources/LazyMemoCore/Model/Memo.swift), [MemoFile.swift](../Sources/LazyMemoCore/Model/MemoFile.swift), Core 서비스·Recall·Tidy, [NowSeen.swift](../Sources/LazyMemoWidgetsCore/NowSeen.swift), [NowBand.swift](../ios/LazyMemo/NowBand.swift), [StackView.swift](../ios/LazyMemo/StackView.swift), [HomeView.swift](../ios/LazyMemo/HomeView.swift), `ios/LazyMemoWidgets/`, 맥 메뉴·캡처·메모 창.

필드·상태 전이·기존 파일 이행을 짧게 문서화한 뒤 구현한다. 순서: 파일 읽기/쓰기 호환 → 서비스 행동/되돌리기 → 예약/선정 규칙 → 폰/맥 → 위젯. UI에서 독자적으로 완료/알림 규칙을 만들지 않는다. 일반 메모에 완료 버튼을 모두 붙이기보다 항목의 용도에 맞는 주 행동을 둔다.

통과 조건: 구형 `.md`·알 수 없는 frontmatter·사진·날짜·원문 왕복 보존. 완료/보관/되돌리기·자정·시간대 변경·반복 회차·동시 수정 후 규칙 일치. 폰 완료가 동기화된 맥·위젯에도 반영됨. 기기별 오늘 숨김이 전역 완료로 오인되지 않음. ‘지금’에 3개만 보여도 전체 미처리로 접근 가능.

### 묶음 5 — 동기화 충돌을 사람이 복구할 수 있게 한다

플랜: `#conflict-recovery`. 파일 조정은 기존 `lazymemo-upgrades-2026-09#file-coordinator`와 연결한다.

중심: [ConflictSettlement.swift](../Sources/LazyMemoCore/Storage/ConflictSettlement.swift), [MemoVault.swift](../Sources/LazyMemoCore/Storage/MemoVault.swift), `MemoStore`, 양쪽 오류/복구 화면. 진 판본을 무조건 없애거나 최신 시각만 믿고 합치지 않는다. 충돌 발생 사실·두 판 비교·둘 다 보존/선택을 제공한다. 기존 휴지통 복구도 유지한다.

통과 조건: 양 기기 오프라인 편집, 앱+위젯+확장 쓰기, 체크박스·본문·첨부 동시 변경. 텍스트뿐 아니라 참조 첨부도 보존되는지 확인한다. 원자적 쓰기·파일 조정·충돌 해결은 각각 다른 문제이므로 하나로 모두 해결됐다고 보고하지 않는다.

### 묶음 6 — 사용 증거를 얻고 다음 매력을 추가한다

플랜: `#release-regressions`, `#evidence-next-scope`.

기본 경험이 통과하면 스크린샷 공유→원본 저장→선택적 OCR→날짜 제안→다시 보기를 다음 후보로 올린다. 원본 저장이 OCR 실패에 종속되지 않게 한다. `lazymemo-upgrades-2026-09#photo-ocr`, `#phone-photo-attach`가 기존 실행 자리다.

AI는 근거 원문 찾기 중심으로 검증한다. 과거 M4 결과를 최소 지원 기기의 성능 증거로 쓰지 않는다. `lazymemo-jarvis-local`의 모델·실기기 게이트를 그대로 사용한다. 모델을 새로 받거나 엔진을 바꾸는 작업은 이번 첫 묶음의 선행 조건이 아니다.

## 6. 기존 플랜과의 연결

새 플랜은 **제품 규칙 변경**만 추적한다. 아래 기존 항목을 복사해 중복 완료하지 않는다.

|---|---|
| `lazymemo-recall#recall-device` | 잠금·종료·권한 거절/재허용·맥 왕복 실기기 검증 |

| `lazymemo-upgrades-2026-09#file-coordinator` | 공유 파일 조정 |
| `lazymemo-upgrades-2026-09#photo-ocr`, `#phone-photo-attach` | 핵심 검증 뒤 스크린샷/사진 확장 |

처음 실행할 명령 예시:

```sh
git status --short
./scripts/test.sh --filter 'TidyRuleTests|TidySweepTests|RecallTests|ReminderCenterTests|DueClockTests'
```

실제 변경 뒤에는 `--skip-build`를 사용하지 않는다. 새 의존성 전체 저장소나 모델을 다운로드하지 않는다. 300MB 이상 새 산출물 예상 시 크기·위치를 먼저 알리고, iOS DerivedData는 `.build/ios` 또는 `LAZYMEMO_DERIVED`를 따른다. 관련 시험이 통과하면 변경 영향에 맞는 전체 시험·번들·시뮬레이터 확인으로 진행한다. 다른 세션의 공유 빌드를 침범하지 않는다.

## 9. 성공 여부를 판단하는 실험

먼저 신규 사용자 5명에게 설명 없이 저장·다시 찾기·미루기·완료를 시킨다. 이후 기존 계획의 10명/7일 시험을 수행한다. 연락 대상이나 계정이 제공되지 않았다면 임의로 외부 메시지를 보내지 말고 관찰 과제와 기록 양식을 준비한다.

내부 판단선은 첫 실제 메모 저장/재발견 8명 이상, 구체적으로 도움이 된 회상 7명 이상, 마지막 이틀 자발적 재사용 5명 이상이다. 업계 평균이나 성공 보장 수치가 아니다. 작동 결함·방해 사례는 별도로 기록한다. 본문을 몰래 수집하거나 기존 프라이버시 약속을 깨는 분석 도구를 추가하지 않는다.

사용자가 기록은 하지만 다시 보기에서 가치를 못 느끼면 그 원인을 먼저 관찰한다. 모델·테마·기능을 더하면 해결된다고 가정하지 않는다. **다음 세션은 ‘무엇을 만들었나’와 함께 ‘사용자가 어떤 일을 더 쉽게 끝내게 됐나’를 보고해야 한다.**
