## 문제 정의

v1 이 돌아가고 마찰 제거·자동 치우기·첫 종이까지 끝났다 (`lazymemo-lazy-comfort` 결론). 이제 물어야 할 것은 다르다 — **이 앱을 쓸 이유가 다른 앱을 쓸 이유보다 큰가.** 붙임쪽지 앱도, 날짜에 붙는 노트 앱도, 빠른 입력 앱도, Apple Notes 를 조종하는 MCP 서버도 이미 있다. 그 사이에서 lazymemo 가 **혼자 서 있는 칸**이 있는지, 있다면 그 칸을 무엇으로 못 박을지 정해야 한다.

### 조사한 것 — 경쟁 지형은 네 진영이고, 넷 다 한 칸씩 비어 있다

| 진영 | 대표 | 가진 것 | **비어 있는 것** |
|---|---|---|---|
| 바탕화면 붙임쪽지 | Apple Stickies(수년째 방치 — iCloud 동기화·검색·태그·내보내기 전부 없음), Noticky($6.99, 전체화면 위 상주, 2026-03 Tahoe 대응), SideNotes(가장자리 패널), Antinote($5, 임시 스크래치패드 — 인라인 계산·통화 변환·OCR·AutoPaste·타이머·JS 확장) | 항상 보인다 | **시간 구조가 없다.** 달력이 없으니 "언제"를 못 다루고, 그래서 쪽지는 영원히 쌓인다 |
| 날짜에 붙는 노트 | Agenda(날짜 중심, 캘린더 이벤트와 노트를 잇는다), NotePlan(마크다운 로컬 파일 + 캘린더 + 타임블로킹) | 시간이 구조다 | **바탕화면이 없다.** 열어야 보인다. Agenda 는 거기 더해 **폐쇄 포맷** — 노트를 파일로 못 꺼낸다 |
| 빠른 입력 | Drafts(텍스트 인박스 → 다른 앱으로 라우팅), Tot(7칸 스크래치패드), Heynote, Apple Quick Note, Raycast | 잡는 마찰이 0 에 가깝다 | **보관이 없다.** 잡아서 남의 앱으로 보내는 것이 목적이라, 잡은 것이 어디로 갔는지는 남의 사정 |
| AI 연동 | Apple Notes MCP 서버들(sweetrb 유지 중 / RafalWilinski 400+★ 이지만 2024 말 이후 정지), Macuse, Apple-MCPs | Claude 가 메모를 만들 수 있다 | **전부 AppleScript·JXA 로 남의 앱을 조종한다.** 느리고 깨지기 쉽고, 무엇보다 **결과가 "열어야 보이는 앱" 안에 떨어진다** |

### 여기서 나온 결론 — 우리가 가진 유일한 것

lazymemo 는 **바탕화면 상주 + 시간 구조 + 열린 파일 포맷 + 네이티브 MCP** 가 동시에 있는 유일한 칸이다. 이건 새로 만들 것이 아니라 **이미 내린 결정들의 합**이다 (D1 창 구조, D5 달력, 마크다운 정본, D3 MCP 방향).

그리고 그 합에서 한 문장이 나온다.

> **다른 앱의 MCP 는 "남의 앱에 결과를 넣는다". lazymemo 는 MCP 서버가 곧 화면이다.**
>
> Claude 가 만든 메모는 열어야 보이는 목록의 한 줄이 아니라 **바탕화면에 놓인 종이**다. 게다가 `DayClock`·`DueClock` 이 이미 있으므로, **그 종이가 언제 떠오를지도 Claude 가 정할 수 있다.**

즉 lazymemo 의 자리는 노트 앱이 아니라 **에이전트의 출력 표면(output surface)** 이다. 에이전트는 늘 "결과를 어디에 두지" 에서 막히고, 지금 답은 터미널 스크롤백이거나 열어야 보이는 앱이다. 우리에겐 **닫히지 않는 화면**이 있다. 아래 후보들은 전부 이 문장을 못 박는 방법이거나(A·B·C·D), 그 문장을 실제로 쓸모 있게 만드는 받침(E·F·G·H)이다.

## 후보 해결 방안

### 방안 A — Claude 가 시각을 정해 종이를 놓는다 {#opt-agent-surface}

MCP 에 `surface_at` 을 연다. `create_memo`/`update_memo` 의 인자로 받고, 이미 있는 메모를 띄우는 `surface_memo(id, at)` 를 더한다. 그러면 이렇게 된다 — "회의 30분 전에 이 메모 띄워줘", "금요일 아침에 이거 다시 보여줘".

- **장점**: 이 앱만 할 수 있는 일이다. 남의 앱에 결과를 넣는 MCP 서버는 시각을 정할 수 없다 — 띄울 화면이 없기 때문이다. **새 권한을 요구하지 않는다** (시스템 알림이 아니라 `riseBriefly` 창 레벨 전환). 배선이 이미 다 있다.
- **단점**: `due`/`at` 과 의미가 겹쳐 보일 위험. "일정의 시각"과 "떠오를 시각"은 다른 것이고(회의는 3시, 종이는 2시 30분), 그 차이가 UI 에서 읽혀야 한다.
- **비용**: 낮음. `Memo` 에 필드 하나 + `DueClock` 에 갈래 하나 + MCP 인자. 프론트매터는 `preserved` 가 미지의 키를 이미 보존하므로 파일 호환이 깨지지 않는다.

### 방안 B — 「정리해줘」를 사용자가 발명하지 않게 한다 (MCP prompts) {#opt-mcp-prompts}

MCP 사양의 `prompts/list`·`prompts/get` 을 구현한다. Claude Desktop 이 이것을 슬래시 명령으로 보여주므로, 사용자는 프롬프트를 지어내지 않고 고르기만 한다 — `/이번 주 정리`, `/오늘 뭐부터`, `/흩어진 메모 합치기`, `/지난달 뭐 했더라`.

- **장점**: `lazymemo-lazy-comfort` 의 문제 3("정리를 대신 해준다의 절반이 앱 밖에 있다")을 정면으로 친다. 지금은 MCP 를 등록해도 **무엇을 시킬 수 있는지 모르면 아무 일도 일어나지 않는다.** 도구 목록은 모델이 읽고 프롬프트 목록은 사람이 읽는다 — 비어 있는 쪽이 사람 쪽이다.
- **단점**: 프롬프트 문구가 곧 제품이다. 나쁜 프롬프트는 나쁜 정리를 만들고, 그건 "치워야 할 것을 하나 더" 가 된다 ({#opt-g} 를 보류한 이유와 같은 위험).
- **비용**: 아주 낮음. `JSONRPC.swift` 에 메서드 둘 + 문자열. 코드보다 문장을 고르는 데 시간이 든다.

### 방안 C — 앱 안에서 Claude 를 부른다 (`claude` CLI 서브프로세스) {#opt-claude-cli}

설계문서가 F-2 로 미뤄 둔 경로. `which claude` 로 있으면 켜지고 없으면 **조용히 없다.** 종이 위 조작 하나(「정리」)와, 하루 한 번 아침에 놓이는 종이 한 장(오늘의 브리핑).

- **장점**: Claude Desktop 을 설정한 사람만 정리를 받는 지금 구조를 깬다. API 키 불필요 원칙도 그대로다(구독 인증 재사용). 그리고 **아침 브리핑은 이 앱의 완성형**이다 — 방안 A 의 "Claude 가 종이를 놓는다" 를 사용자가 아무것도 하지 않아도 매일 일어나게 만든다.
- **단점**: CLI 가 없는 사용자에겐 존재하지 않는 기능이라, 광고할 수 없고 스크린샷에도 못 넣는다. 서브프로세스 실패·지연·비용을 종이 위에서 어떻게 말할지가 통째로 새 UI 문제다. 앱이 처음으로 "기다리는 상태" 를 갖게 된다.
- **비용**: 높음. 넷 중 유일하게 새 실패 유형을 들여온다.

### 방안 D — 어디서든 던지기: URL 스킴 + CLI + 서비스 메뉴 {#opt-throw-in}

입력의 문을 세 개 연다 — `lazymemo://add?text=…`(Info.plist 에 `CFBundleURLTypes`), 서비스 메뉴 「lazymemo 에 적기」(`NSServices`), 그리고 `lazymemo add "…"` CLI(MCP 바이너리에 서브커맨드 하나 — `MemoService` 를 이미 쓰고 있다).

- **장점**: 이 문 하나로 Raycast·Alfred·단축어·Hazel·cron·git hook·**다른 에이전트**가 전부 입력 경로가 된다. 붙임쪽지 진영에 이걸 가진 앱이 없다. 그리고 이것은 방안 A 의 짝이다 — A 가 "Claude 가 놓는 문" 이면 D 는 "무엇이든 던지는 문" 이고, 둘이 있어야 바탕화면이 표면이 된다. `lazymemo-lazy-comfort` 의 {#opt-d} 중 **권한도 번들 구조도 건드리지 않는 부분만** 떼어낸 것이다.
- **단점**: URL 스킴은 아무나 두드릴 수 있는 문이다. 글자만 받고 파일·명령은 받지 않는 선을 못 박아야 한다. 공유 확장(별도 번들 타깃)은 여전히 범위 밖.
- **비용**: 낮음. plist 두 항목 + 핸들러 + 서브커맨드.

### 방안 E — 아이폰에서 던지기, iOS 앱 없이 {#opt-shortcut-drop}

파일이 정본이고 `VaultWatcher` 가 폴더를 보고 있으므로, vault 를 iCloud Drive 에 두면 **단축어 하나로 아이폰에서 메모가 꽂힌다** — `notes/YYYY/MM/` 아래에 .md 파일 하나를 쓰면 끝이다. 우리가 만들 것은 코드가 아니라 **단축어 하나와 README 한 문단**이다.

- **장점**: 열린 파일 포맷이 낳은 공짜 기능이고, **Agenda 는 폐쇄 포맷이라 원리적으로 못 한다.** "동기화 백엔드가 없다" 를 약점이 아니라 강점으로 뒤집는다.
- **단점**: iCloud 반영 지연이 실측 20분~수 시간까지 보고된다. 정직하게 적지 않으면 "안 된다" 로 읽힌다. ULID 파일명 규칙을 단축어가 흉내내야 하는데, 그러느니 **아무 이름이나 받아 앱이 정본 이름으로 고쳐 앉히는 쪽**이 맞다 — 그 관용이 코드에 있는지 확인이 필요하다.
- **비용**: 거의 0 (관용 확인이 아니라면).

### 방안 F — 반복되는 날 {#opt-recurring}

`every: 매주 화요일`. 게으른 사람에게 가장 자주 필요한 것(분리수거, 약, 정기결제, 주간 보고)이 지금은 **적을 수가 없다.** `NaturalDateParser` 가 "매주 화요일 8시" 를 읽게 확장한다.

- **장점**: 차별 기능은 아니지만 **없으면 앱을 못 믿는 종류의 구멍**이다. "적었는데 그냥 지나갔다" 를 반복 일정이 가장 많이 만든다.
- **단점**: `Tidy.past`("지난 일정은 다음 날 물러난다")와 정면으로 부딪힌다. 반복 일정은 지나도 물러나면 안 되고, 다음 회차로 걸어가야 한다. 규칙 설계가 먼저다.
- **비용**: 중간.

### 방안 G — 진짜 캘린더를 읽는다 (EventKit) {#opt-eventkit}

D5 가 후순위로 미뤄 둔 것. 지금 달력은 **내 메모만 있는 달력**이라, 실제 회의가 안 보인다. 읽기 전용으로 시스템 캘린더를 겹쳐 그린다.

- **장점**: 방안 A 를 진짜로 쓸모 있게 만든다 — "회의 30분 전에 띄워줘" 가 성립하려면 회의를 알아야 한다. Agenda·NotePlan 이 이걸 하고 있고, 없으면 우리 달력은 계속 반쪽으로 보인다.
- **단점**: **권한 프롬프트가 하나 생긴다.** "첫 실행에서 사용자를 시스템 설정으로 보내지 않는다"(§8)와 부딪히므로, 달력을 **처음 여는 순간에만** 묻고 거절하면 영영 안 묻는 형태여야 한다. 그리고 남의 일정을 우리 종이로 착각하게 만들면 안 된다 — 재질이 달라야 한다.
- **비용**: 중간.

### 방안 H — 게으른 찾기: 시간과 형태로 되짚기 {#opt-recall}

`lazymemo-lazy-comfort` 의 {#opt-e} 와 `lazymemo-pro-lazy-ux` 의 {#opt-fuzzy-temporal-search} 가 같은 것을 가리키고 있었다 — 빠른 입력에 시간·형태 칩(`@어제`, `@지난주`, `#링크`, `#사진`)을 두고 결과 5개 상한을 넓힌다.

- **장점**: 메모가 200장이 되면 "그때 그거" 로 돌아갈 길이 지금은 사실상 없다. 차별 기능은 아니지만 **없으면 앱이 무너지는 지점**이고, Stickies 가 죽은 이유 중 하나가 정확히 이것이다(검색이 없다).
- **단점**: 근본 해결은 아니다 — 게으른 사람은 검색어를 떠올리기도 싫어한다. 자동 치우기와 짝을 이룰 때만 의미가 있다.
- **비용**: 낮음~중간. 인덱스 쿼리 확장.

### 방안 I — 장소: 새 축이지만 자리를 바꾸지 않는다 {#opt-place}

사용자 요청으로 뒤늦게 들어온 안이고, 다른 여덟과 성질이 다르다 — **「시간이 유일한 구조다」(§14.2)를 건드린다.** 그래서 먼저 그 충돌부터 푼다.

**푸는 방식: 장소는 자리를 정하지 않는다.** 날짜가 붙으면 종이가 물러나고 달력이 맡는다(§7.2). 장소가 붙어도 **종이는 그대로 있다.** 지도 뷰도, 장소 목록도, 「장소별 보기」도 만들지 않는다 — 그것들은 전부 사용자가 유지해야 하는 구조이고, 게으른 사람은 유지하지 않는다. 장소는 종이에 찍힌 **잉크 자국 하나**이고, 누르면 지도가 열린다. 그러면 구조는 여전히 시간 하나이고, 장소는 날짜와 같은 **부사**다.

앱 안에 지도를 들이지 않는 이유가 하나 더 있다 — 재질이 둘이 된다(§14.5 「재질은 하나 — 종이」). 유리를 세 번 시도했다 되돌린 것과 같은 이유로, 지도는 종이가 아니다.

**구체**

1. `place:` 프론트매터 한 줄, 선택적으로 `geo: 37.4979,127.0276`. 좌표가 없어도 문자열만으로 지도에 검색어로 넘길 수 있다 — 파일이 사람이 읽는 것으로 남는다.
2. **읽는 규칙은 둘뿐이다.** `@강남역` 처럼 `@` 다음의 낱말(캘린더·슬랙·인스타에서 이미 장소에 쓰는 기호라 배울 것이 없다)과, **한국 주소 패턴**(`…시/도 …구/군 …로/길 숫자`, 우편번호 5자리). **산문에서 추측하지 않는다** — 그건 {#opt-g} 를 보류한 덫과 같다.
3. `⌥⌘L` 「지금 여기」 — `⌥⌘V` 의 형제. 현재 위치를 역지오코딩해 종이 한 장. "여기 주차했다", "이 가게 뭐지".
4. **달력 줄에 함께 뜬다** — `3시 치과 · 강남역`, 그 줄에서 바로 길찾기. **나가기 전에 필요한 전부가 한 줄에 있다.** 시간과 장소를 함께 가진 값이 여기서 나온다.
5. MCP 에 `place`/`geo` 를 열면 "강남에서 할 일 뭐 있어?" 가 성립한다.
6. **{#opt-shortcut-drop} 과 공짜로 합류한다** — 단축어가 「현재 위치」를 읽어 `place:`+`geo:` 가 박힌 .md 를 vault 에 떨구면, **iOS 앱 없이 아이폰 위치 메모**가 된다. macOS 쪽 코드는 0줄이다.

- **장점**: 게으른 사람이 실제로 잃어버리는 것 두 가지(언제·어디)를 앱이 다 잡는다. 붙임쪽지 진영에 장소를 다루는 앱이 없고, Agenda·NotePlan 은 캘린더 이벤트의 장소를 보여줄 뿐 **적는 마찰**을 줄이지 않는다.
- **단점**: 권한이 하나 생긴다(`NSLocationWhenInUseUsageDescription` — 지금 Info.plist 엔 usage description 이 **하나도 없다**). §8 원칙에 따라 **`⌥⌘L` 을 처음 누를 때만** 묻고, 거절하면 그 단축키는 조용히 없는 것이 되어야 한다. 그리고 한국 주소 패턴은 오탐이 나면 안 되는 자리다.
- **비용**: 중간. 필드·파서·잉크·단축키·달력 줄로 나뉘고, 각각은 작다.

### 방안 J — 가면 떠오른다 (지오펜스) {#opt-geofence}

{#opt-agent-surface} 의 장소판. 마트 근처에 가면 장보기 종이가 스스로 떠오른다. **이 앱에서 가능한 가장 게으른 기능**이고, 「적어 놓고 잊는 것을 앱이 거든다」의 완성형이다.

- **장점**: 시간 알림은 자리를 비우면 놓치지만, 장소 알림은 **그 자리에 갔을 때** 온다. 놓칠 수가 없다.
- **단점**: **`Always` 위치 권한이 필요하다.** 이건 링크 카드(§9.3)와 비교가 안 되는 무게의 약속 변경이고, 프라이버시 문단을 통째로 다시 써야 한다. 배터리도 사용자가 묻는다.
- **비용**: 중간. 그러나 **신뢰 비용이 크다** — 기본 꺼짐, 설정에서 명시적으로 켤 때만, 그리고 왜 켜져 있는지가 메뉴에서 보여야 한다({#opt-place} 와 별개 항목으로 두고 마지막에 놓는 이유).

## 결론

**열 안 전부 채택.** 사용자가 "다 만들고 싶다" 고 정했고, 조사 결과 이 열 개는 서로 경쟁하는 안이 아니라 **한 문장의 부분들**이었다 — *lazymemo 는 언제·어디를 잡아 두고, 그것을 에이전트가 놓고 갈 수 있는 바탕화면이다.*

순서만 정한다. 기준은 **권한 비용 오름차순**이다 — 이 앱의 가장 값진 자산이 "첫 실행에 아무것도 묻지 않는다" 이므로, 묻지 않고 되는 것을 먼저 다 하고 묻는 것을 뒤로 민다.

| 단계 | 무엇 | 권한 | 왜 여기 |
|---|---|---|---|
| 1 | {#opt-throw-in} · {#opt-mcp-prompts} · {#opt-shortcut-drop} | **없음** | 가장 싸고, 뒤의 전부가 이 문으로 들어온다 |
| 2 | {#opt-agent-surface} | **없음** | 차별의 핵심. 배선(`riseBriefly`)이 이미 있다 |
| 3 | {#opt-place} | 위치(사용 중) — **`⌥⌘L` 을 처음 누를 때만** | 언제의 짝인 어디. 자리를 바꾸지 않으므로 구조를 건드리지 않는다 |
| 4 | {#opt-eventkit} · {#opt-recurring} · {#opt-recall} | 캘린더 읽기 — **달력을 처음 열 때만** | 차별이 아니라 **없으면 무너지는 구멍**들 |
| 5 | {#opt-claude-cli} · {#opt-geofence} | Always 위치 | 새 실패 유형과 큰 신뢰 비용. 앞의 넷으로 문장이 선 뒤에 |

보류했던 {#opt-g}(규칙 기반 자동 묶기)는 그대로 보류다. {#opt-place} 의 장소 인식을 `@낱말`과 주소 패턴 **둘로 제한**한 것이 같은 판단이다 — 앱은 확실한 것만 읽고, 애매한 것은 Claude 가 맡는다.

실행 단위로 쪼갠 것이 plan `lazymemo-v2-surface-place` 이고, 이 문서는 여기서 닫는다.
